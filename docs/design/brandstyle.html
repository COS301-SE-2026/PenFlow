THEME

The Theme

Running a scan for OSINT data on an attack surface is like a submarine sweeping the ocean floor with sonar — probing the dark for signals, surfacing only what the target has unknowingly left exposed.

THE OCEAN

The deep-navy palette evokes crushing depth and the unknown. Just as the ocean conceals what lurks beneath, a target network hides its vulnerabilities until something with the right instruments looks closely enough. PenFlow allows the user to see for themselves.

THE SUBMARINE

The submarine is the product's spirit animal: it operates silently, reads its environment through sonar, and surfaces only with actionable intelligence.

THE SCAN

Cyan is the sonar pulse — sent out into the dark and returning with what it finds. Every interactive element that confirms an action or surfaces data uses cyan, the same way a submarine's sonar cuts through the unknown and brings the hidden into view.

SECURITY & TRUST

Despite the dark aesthetic, the UI must feel controlled and trustworthy — not chaotic. Tight grid alignment, deliberate whitespace, and restrained motion signal expertise. Red (#ff5f4e) surfaces danger without panic. The overall effect is a product that feels like it has already assessed the situation and is calmly reporting back: you are in capable hands.

TONE

Tone

BUILT FOR EVERYONE

Security tooling has a reputation for being impenetrable. PenFlow pushes back against that. Whether the user is a CTO reviewing an executive summary or a junior developer seeing a CVE score for the first time, the interface meets them where they are. Labels are written in plain language first, technical identifiers second. No user should feel like the product was built for someone else.

FRIENDLY, NOT CASUAL

Approachable does not mean informal. PenFlow is friendly in the way a trusted expert is friendly — warm enough to make a first-time user feel welcome, precise enough to make a seasoned analyst feel respected. Copy avoids jargon walls and acronym soup, but it also avoids over-explaining to people who clearly know what they are doing. The interface reads the room and responds accordingly.

EXPLAINING THE SYSTEM

Key sections of the UI carry short contextual explanations — not tooltips buried behind hover states, but visible, readable callouts that explain what a section shows and why it matters. A user who has never run a penetration test should finish their first PenFlow report with a clearer understanding of their attack surface than when they started. Education is a feature, not an afterthought.

TONE IN PRACTICE

A scan completion is confident: "Scan complete — 14 findings detected." A critical finding is sober: "Critical · Port 22 exposed to all traffic." An explanation panel is reassuring: "This means your login page is reachable without authentication. Here is what to do next." Same product, same voice, adjusted for what the user needs in that moment.

WEIGHTS ARE A LADDER

400 / 500 / 600 / 700

Each weight has a job. Regular (400) carries body copy. Medium (500) adds emphasis without shouting. Semi-bold (600) anchors labels, nav items, and UI controls. Bold (700) is reserved for display numbers and critical values where the figure itself needs to land before the label is read. Mixing adjacent weights flattens the hierarchy — step at least two rungs when creating contrast.

BUTTONS SIZING & SPACING

Buttons use clamp() font sizing with 0.08em letter spacing. Padding is 12px 28px for standard buttons, height: 48px for pill variants. Minimum touch target is 44×44px. Never place two primary buttons side by side — one primary action per context.

SEVERITY BADGES

SIZING & COLOUR

Badges are padding: 2px 9px, border-radius: 4px, font size 0.68rem in Bebas Neue. Text colour is always #0a1628 (dark) — never white — on the severity background. Minimum width is dictated by the longest label (CRITICAL).

PLACEMENT RULES

Badges always appear to the right of the asset or finding they describe — never above or below. They are right-aligned in table cells. A badge must never appear without the text label; colour alone does not satisfy accessibility requirements. Do not resize badges or change their border-radius.

CARDS

SIZING & SPACING

Cards use padding: 28px 32px on desktop, border-radius: --radius-xl (14px), and a 1px solid --col-edge border. Background is --col-deep. Internal elements follow a consistent stack: label → title → body, each separated by 10–12px.

05 · ACCESSIBILITY

Accessibility

COLOUR CONTRAST

PenFlow targets WCAG 2.2 Level AA throughout. Body text (--col-text on --col-navy) achieves 12.4:1 — well above the 4.5:1 minimum. Large text and UI components require 3:1. Severity badge text uses #0a1628 (dark) on the severity colour; all severity colours meet the 3:1 threshold. Never render informational text in --col-muted alone against a dark background — it does not pass at small sizes. When in doubt, use a contrast checker before shipping.

GOOGLE LIGHTHOUSE

Google Lighthouse is an open-source automated auditing tool built into Chrome DevTools that analyses web applications across accessibility, best practices, performance, and SEO. It surfaces issues like missing alt text, poor contrast, absent ARIA labels, and non-semantic markup before they reach users. The scores shown are actively maintained — any drop is fixed before the next release.
